# doc-to-markdown

把外部規格文件（pdf/word/ppt/excel）轉換成**單一結構化 `.md` 檔**，但**只轉跟這次開發需求有關的部分**，不是整份文件照單全收。轉換工作固定拆成「規劃 → 轉檔」兩個獨立 subagent 依序完成，規格上的模糊點一律在規劃階段就問使用者，不留到轉檔時才冒出來。

## 適用情境

觸發條件（符合其一即可）：
- 使用者提供或指向一個 `.pdf` / `.doc` / `.docx` / `.pptx` / `.xlsx` 檔案，並要求轉換、整理、摘要成 Markdown
- 使用者說「幫我把這份規格轉成 md」「轉成 Claude 看得懂的格式」「整理成文件方便之後引用」
- 上傳的規格文件需要被後續開發/規劃流程讀取（例如作為 `senior-engineer` 或其他開發流程的輸入）

不適用：使用者只是要「讀取/摘要」文件內容回答問題，並不需要落地成 `.md` 檔案時，直接用對應的 pdf/docx/pptx/xlsx skill 讀取回答即可，不必跑本流程。

## 前提：要有「開發需求描述」才能篩選範圍

本流程的核心是「只轉跟開發需求有關的部分」，所以動手前一定要先有明確的開發需求描述（這次要做什麼功能、要改什麼、目的是什麼）。

- 使用者訊息裡已經講清楚要開發什麼 → 直接使用該描述
- 使用者只丟了檔案、沒講清楚要做什麼開發 → 先問使用者這次的開發需求是什麼，不要自己臆測範圍，也不要退回成「整份轉換」

## 步驟

### 步驟 0：取得原始文字，不要盲讀二進位檔

**禁止**直接用 Bash/Read 硬解析二進位內容。依副檔名呼叫對應的既有 skill 取出文字與結構：

| 副檔名 | 使用的 skill |
| --- | --- |
| `.pdf` | `anthropic-skills:pdf` |
| `.doc` / `.docx` | `anthropic-skills:docx` |
| `.pptx` | `anthropic-skills:pptx` |
| `.xlsx` | `anthropic-skills:xlsx` |

把抽出的原始文字/表格/結構存成暫存檔（放在 scratchpad，不放專案目錄），作為後面兩個 subagent 的輸入。

**環境缺 pandoc/LibreOffice 時的 `.doc` 已知限制**：`anthropic-skills:docx` 處理舊版 `.doc`（OLE 複合檔案格式）的標準做法是用 `pandoc` 或 `soffice` 轉出內容；若環境沒裝這兩者，會退而求其次改用 Microsoft Word 的 COM 自動化。這條路上有個已知陷阱：先用 `SaveAs`/`SaveAs2` 把 `.doc` 另存成 `.docx`、再走一般 docx 解析流程，這個 `SaveAs` 呼叫在部分機器上會**永久卡住不回傳**——原因是 Word 在存檔時可能跳出模態對話框（相容性檢查、格式確認、連結物件更新、巨集安全性警告），COM 自動化通常把 Word 開成不可見視窗，沒有人能點掉這個對話框，呼叫就永遠卡住。

遇到這個情境時：
- **不要把「先轉 docx 再解析」當必經路徑**：既然最終要的只是段落文字、樣式、表格內容，可以直接對 `Documents.Open` 開啟的文件物件用 COM 逐段落讀取（`Paragraphs`/`Tables`/`Range.Style`），寫成暫存純文字檔即可，不必先存成 `.docx` 中間格式。
- 若仍需要 `SaveAs`（例如要保留原生表格 XML 結構），開檔與存檔前先設定 `DisplayAlerts = 0`（`wdAlertsNone`）、`Documents.Open(..., ConfirmConversions:=False, ReadOnly:=True)`、`Options.UpdateLinksAtOpen = False`，可擋掉大部分會跳對話框的來源；並幫這次呼叫包一層時限（timeout），超時就強制關閉 `WINWORD.EXE` 行程再降級成上一點的直接讀取法，避免整個轉檔流程卡死。

### 步驟 1：規劃（強制使用 `doc-to-markdown-planner`，模型 opus）

呼叫 `doc-to-markdown-planner` subagent，在 prompt 裡提供：
- 使用者的開發需求描述
- 步驟 0 抽出內容的暫存檔路徑
- 原始文件檔名

這一步是唯讀分析，不會產出 `.md`。它會回傳：轉換範圍（哪些章節列入/排除及理由）、章節對應、**規格待確認清單**、建議的輸出檔名與路徑。

### 步驟 2：規格問題必須在這裡問完，不要留到轉檔

若規劃 subagent 回傳的「規格待確認清單」非「無」，**在進入步驟 3 之前**，把清單內容呈現給使用者確認（可用 AskUserQuestion 或直接在對話中列出詢問）。等使用者回覆後才繼續，不要先轉檔再回頭補問。

若原始文件所在資料夾已存在同名 `.md`，也在這裡一併詢問使用者是否覆蓋；若資料夾無法寫入（唯讀、權限不足），改詢問使用者要輸出到哪個非專案路徑。

### 步驟 3：轉檔（強制使用 `doc-to-markdown-converter`）

呼叫 `doc-to-markdown-converter` subagent，在 prompt 裡提供：
- 步驟 0 抽出內容的暫存檔路徑
- 步驟 1 定案的轉換範圍與章節對應
- 步驟 2 使用者對規格待確認清單的回覆（若有）
- 確認過的輸出檔案完整路徑

這兩個 subagent 定義在本 plugin 的 `agents/` 資料夾（隨 plugin 一起載入，`subagent_type` 用純名稱 `doc-to-markdown-planner`、`doc-to-markdown-converter` 即可）；環境裡找不到時退而求其次用 `general-purpose`，並在 prompt 裡自己補上該角色的職責與限制（規劃只分析不寫檔、轉檔只依定案範圍轉不自己判斷範圍）。

## 轉換原則（轉檔 subagent 依此執行）

- **範圍限定**：只轉規劃階段定案的章節，不相關的章節不轉入
- **章節階層**：原文件的標題層級（章/節/條）對應到 Markdown `#`/`##`/`###`，不可打散或合併層級
- **表格**：一律轉成 Markdown 表格語法，不得用截圖、圖片或純文字條列代替
- **圖片/圖表**：若無法轉成文字，於原位置標註 `[圖：<簡述內容或用途>]`，保留語意與位置，不可略過不提
- **專有名詞與代號**：規格編號、產品代號、系統代號等一律照抄原文，不簡化、不翻譯、不重新編號
- **不拆檔**：範圍內無論章節多寡，一律輸出成單一 `.md` 檔，用 `#`/`##`/`###` 標題維持章節結構即可，不要拆成多檔、也不要另建 `index.md`
- **忠實度優先**：轉換是「還原成可讀格式」，不是摘要或改寫；不要自行增刪內容、不要幫使用者下結論

## 輸出位置與命名規則

- **不寫入專案資料夾**：輸出的 `.md` 一律放在**原始文件所在的資料夾**，與來源檔並列，不要放進專案目錄（不建 `specs/`、不放 repo 內任何位置）
- 輸出單一檔案：`<原始文件所在資料夾>/<原檔名（去副檔名）>.md`
- 檔名一律使用原文件的檔名（去除副檔名），中文可保留

## 範例

輸入：`D:\Docs\CAMA10_會員點數規格書.pdf`，開發需求：「要在會員點數查詢頁加上點數到期日顯示」

規劃 subagent 判斷：只有「點數餘額/到期日相關章節」「會員點數資料表定義」跟這次開發有關，其他模組沿革、跟點數無關的附錄排除。

輸出：`D:\Docs\CAMA10_會員點數規格書.md`（單一檔，只含規劃階段定案範圍內的章節）

轉換前（PDF 原文，表格以圖片呈現）：
```
表 3-1 欄位定義
[會員編號 | VARCHAR(20) | 必填]
[點數餘額 | DECIMAL(10,2) | 必填]
```

轉換後（`CAMA10_會員點數規格書.md` 中對應章節）：
```markdown
## 表 3-1 欄位定義

| 欄位名稱 | 型別 | 是否必填 |
| --- | --- | --- |
| 會員編號 | VARCHAR(20) | 必填 |
| 點數餘額 | DECIMAL(10,2) | 必填 |
```
