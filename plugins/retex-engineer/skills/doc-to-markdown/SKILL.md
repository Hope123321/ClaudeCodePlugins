# doc-to-markdown

把外部規格文件（pdf/word/ppt/excel）轉換成**單一結構化 `.md` 檔**，保留章節、表格與專有名詞，讓後續開發流程（如 `feature-adjust-with-spec-workflow`）能直接讀取。整份文件不論多長都輸出成一個 `.md`，不拆檔。

## 適用情境

觸發條件（符合其一即可）：
- 使用者提供或指向一個 `.pdf` / `.doc` / `.docx` / `.pptx` / `.xlsx` 檔案，並要求轉換、整理、摘要成 Markdown
- 使用者說「幫我把這份規格轉成 md」「轉成 Claude 看得懂的格式」「整理成文件方便之後引用」
- 上傳的規格文件需要被後續開發/規劃流程讀取（例如作為 `specdoc-adjust-planner` 的輸入）

不適用：使用者只是要「讀取/摘要」文件內容回答問題，並不需要落地成 `.md` 檔案時，直接用對應的 pdf/docx/pptx/xlsx skill 讀取回答即可，不必跑本流程。

## 工具/指令：先取原始文字，不要盲讀二進位檔

**禁止**直接用 Bash/Read 硬解析二進位內容。依副檔名呼叫對應的既有 skill 取出文字與結構：

| 副檔名 | 使用的 skill |
| --- | --- |
| `.pdf` | `anthropic-skills:pdf` |
| `.doc` / `.docx` | `anthropic-skills:docx` |
| `.pptx` | `anthropic-skills:pptx` |
| `.xlsx` | `anthropic-skills:xlsx` |

取得原始文字/表格/結構後，才依下方原則整理成 Markdown。

## 轉換原則

- **章節階層**：原文件的標題層級（章/節/條）對應到 Markdown `#`/`##`/`###`，不可打散或合併層級
- **表格**：一律轉成 Markdown 表格語法，不得用截圖、圖片或純文字條列代替
- **圖片/圖表**：若無法轉成文字，於原位置標註 `[圖：<簡述內容或用途>]`，保留語意與位置，不可略過不提
- **專有名詞與代號**：規格編號、產品代號、系統代號等一律照抄原文，不簡化、不翻譯、不重新編號
- **不拆檔**：無論章節多寡、篇幅大小，整份文件一律輸出成單一 `.md` 檔，用 `#`/`##`/`###` 標題維持章節結構即可，不要拆成多檔、也不要另建 `index.md`
- **忠實度優先**：轉換是「還原成可讀格式」，不是摘要或改寫；不要自行增刪內容、不要幫使用者下結論

## 輸出位置與命名規則

- **不寫入專案資料夾**：輸出的 `.md` 一律放在**原始文件所在的資料夾**，與來源檔並列，不要放進專案目錄（不建 `specs/`、不放 repo 內任何位置）
- 輸出單一檔案：`<原始文件所在資料夾>/<原檔名（去副檔名）>.md`
- 檔名一律使用原文件的檔名（去除副檔名），中文可保留
- 若原始文件所在資料夾已存在同名 `.md`，先詢問使用者是否覆蓋
- 若原始文件所在資料夾無法寫入（唯讀、權限不足），改詢問使用者要輸出到哪個非專案路徑

## 範例

輸入：`D:\Docs\CAMA10_會員點數規格書.pdf`

輸出：`D:\Docs\CAMA10_會員點數規格書.md`（單一檔，含全部章節）

轉換前（PDF 原文，表格以圖片呈現）：
```
表 3-1 欄位定義
[會員編號 | VARCHAR(20) | 必填]
[點數餘額 | DECIMAL(10,2) | 必填]
```

轉換後（`CAMA10_會員點數規格書.md` 中對應章節）：
```markdown
## 表 3-1 欄位定義

| 欄位名稱 | 型別 | 是否必填 |
| --- | --- | --- |
| 會員編號 | VARCHAR(20) | 必填 |
| 點數餘額 | DECIMAL(10,2) | 必填 |
```
