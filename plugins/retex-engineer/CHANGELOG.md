# retex-engineer 更版歷程

本文件記錄 `retex-engineer` plugin 的版本異動，供後續維護參考。版號對應 `.claude-plugin/plugin.json` 的 `version` 欄位。

## 1.1.6

- `senior-engineer-planner` 新增輸出項目「規格待確認清單」（開發任務）：規劃階段就要逐項盤點規格不清楚、矛盾或需外部確認之處，標明影響哪個實作步驟、要跟誰確認；除錯任務原有的「不確定的地方」視為同一機制。
- 開發流程（`development.md`）新增檢查點：主流程收到計畫後，若「規格待確認清單」涉及核心行為，**在進入開發 subagent 之前**先呈現給使用者確認，不再讓模糊點無聲流到開發階段才變成 TODO；完工報告的「規格待確認 / 未實作項目」章節區分「規劃階段就發現」與「開發中才冒出來的新發現」。
- 除錯流程（`debugging.md`）補上對應規則：模式 B（主動修改）即使使用者已授權「直接修」，若根因調查的「不確定的地方」會影響修法選擇，仍須先確認再進入開發，因為「直接修」授權的是省略確認動作，不是授權自行決定查無依據的部分。
- 起因：使用者反映流程容易「實作完才發現一大堆 TODO」，這種情況不該算完工；規格/根因的模糊點應該在規劃階段就被攔下來問清楚，而不是等開發完才被動發現。

- 起因：加強觸發方式並減少因提示詞撰寫問題導致沒觸發

## 1.1.4

- `senior-engineer` skill 新增鐵則：開發必須完全依照設計規格執行；規格標示「待確認」或本身含糊不清的部分，只能寫 `TODO` 註解說明待確認事項，不能自行猜測數值或邏輯冒充已實作。
- 完工報告新增「規格待確認 / 未實作項目」章節，強制列出因規格不明確而未實作的部分。
- 起因：`SpecCompletionTool` 評分報告發現實作端擅自把規格要求的「平台代碼」替換成「平台名稱」，並在一個標註 TODO（待客戶確認批號定義）的欄位上自行補了一個沒有依據的固定值，導致 L3 視覺符合度未達門檻。
